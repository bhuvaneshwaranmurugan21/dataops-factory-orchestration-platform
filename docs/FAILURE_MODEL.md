# Failure model

| Failure | Detection | Safe response | Proven locally |
| --- | --- | --- | --- |
| Duplicate logical run | Immutable run-key conflict | Return same run only for same plan | Yes |
| Scheduler dies | Lease expiry | New owner increments fence | Yes |
| Stale scheduler resumes | Fence mismatch | Reject heartbeat and mutation | Yes |
| Duplicate dispatch | Deterministic dispatch key | Return same attempt identity | Yes |
| Conflicting retry | Different identity for same attempt | Reject | Yes |
| Worker overwrites output | Attempt/fence prefix mismatch | Manifest binding rejects it | Yes |
| Manifest tampering | Digest or signature mismatch | Reject before acceptance | Yes |
| Wrong account signer | Execution-profile binding mismatch | Reject | Yes |
| Callback event lost | Callback age + managed API state | Reconciler heartbeats/completes | Adapter-tested; AWS stage required |
| Glue/EMR fails | Authoritative engine status | Send task failure; preserve attempt | Adapter-tested; AWS stage required |
| Mandatory branch missing | Accepted-job fan-in | Block publication | Yes |
| Concurrent publication | Redshift expected-version conflict | One winner; loser retries/reconciles | Yes in local catalog |
| Crash after catalog commit | Redshift history is idempotent | Read authority and mirror/audit | Yes in local catalog |
| KMS/S3/Redshift outage | AWS error and Step Functions timeout | Retry bounded transient class, then fail | AWS stage required |

The failure lab is an invariant suite, not chaos evidence for AWS availability. Its 19 cases are
listed in `evidence/verified-local/failure-lab-summary.json` and regenerated by `make evidence`.
